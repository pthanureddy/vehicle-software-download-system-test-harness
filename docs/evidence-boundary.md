# Evidence Boundary

## Demonstrated

- Python software development for SWDL test automation
- Automated software testing and CI/CD
- Requirements-based higher-level test cases
- Generic multi-ECU update sequencing and software dependency checks
- Simplified bootloader dual-bank activation and rollback behavior
- Package size and SHA-256 integrity checks
- Simulated Ethernet-style loss, retry/resume, corruption, and retry exhaustion
- Structured failure codes, trace evidence, and technical documentation

## Not demonstrated

- Physical vehicle, rig, ECU, or bootloader testing
- Volvo SWDL technology, internal tools, production data, or proprietary architecture
- VIDA, VCATS, Vector CAPL, CANoe, Canalyzer, or Wireshark use
- Real CAN, Ethernet, DoIP, OTA, network-management, or diagnostic communication
- Electrical architecture design or distributed electrical-system expertise
- Embedded C++ implementation
- Safety, security, authenticity, cryptographic-signature, or standards conformance

All vehicle identifiers, ECU definitions, versions, packages, thresholds, and failures are synthetic.

## Real-system extension

A hardware or vehicle implementation would require employer-approved interfaces, protocol specifications, credentials, addressing, secure package authenticity, session and power-state control, timeout/retry policy, network captures, observability, recovery procedures, safety review, and dedicated integration tests. This repository intentionally does not imply those capabilities.
